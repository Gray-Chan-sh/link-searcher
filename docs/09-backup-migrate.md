# 第九章：数据备份与迁移

> 存储位置、手动备份、自动备份、迁移数据、跨平台索引。

---

## 步骤 1：了解数据存储位置

Link-Searcher 的所有数据存储在本地：

| 平台 | 数据目录 |
|------|---------|
| macOS | `~/Library/Application Support/link-searcher/` |
| Windows | `%APPDATA%\link-searcher\` |
| Linux | `~/.local/share/link-searcher/` |

目录内容：

| 文件/目录 | 说明 |
|-----------|------|
| `data.db` | SQLite 数据库（文件追踪、配置、AI 会话等） |
| `index/` | Tantivy 搜索引擎索引文件 |
| `app.log` | 应用运行日志 |
| `backups/` | 自动备份存储目录 |
| `models/funasr/` | FunASR 语音识别模型 |

> FunASR 模型只需下载一次，升级重装后仍在。开发版（`npm run tauri dev`）优先从项目目录读取，打包版只认数据目录。

## 步骤 2：手动备份

1. 进入索引状态页面
2. 点击「手动备份」按钮
3. 系统会在线备份 `data.db` + 索引目录到备份位置
4. 备份完成后，状态栏会显示结果

## 步骤 3：配置自动备份

1. 进入设置 → 系统标签页
2. 开启「自动备份」开关
3. 设置备份间隔天数（如 7 天）
4. 系统会按间隔自动创建备份

> 备份存储在数据目录的 `backups/` 子目录中。

## 步骤 4：迁移数据

如果需要将数据迁移到新位置：

1. 进入设置 → 通用标签页
2. 点击「数据目录」旁的「迁移数据」按钮
3. 在弹出的对话框中选择目标目录
4. 系统自动复制所有数据到新目录
5. 复制完成后，应用自动重启并使用新目录

> 迁移前请确保目标目录有足够的磁盘空间（至少为原数据体积的 1.5 倍）。

## 步骤 5：了解跨平台索引

文件路径在数据库和索引中存储为**相对路径**（相对于监控目录根），而非绝对路径。

这意味着：
- 两个完全同步的目录在不同操作系统上可共享同一份索引数据
- 例如：macOS 上索引的目录，复制到 Windows 后可直接使用
- 适合在多个设备间共享索引

## 补充：增量备份与 ZIP 导出

### 增量备份链机制

每次手动或自动备份时，系统采用增量备份链：

1. 首次备份创建完整快照，包含数据库和所有 Tantivy 索引段（segment）
2. 后续备份通过**硬链接**（hard link）共享未变化的索引段，仅复制新增或修改的段文件
3. 备份链自动合并：当快照数达到 **10 个**时，系统将最早的 N-1 个快照合并为一个整合基线快照，释放冗余空间

这种方式既节省磁盘空间，又保留完整的备份历史。

### 导出为 ZIP 文件

备份链可以导出为单个 ZIP 文件，便于离线存储或跨设备传输：

1. 进入索引状态页面，点击「导出备份」
2. 选择保存位置和文件名
3. 可选择是否启用 **AES-256 加密**（需设置密码）
4. 导出完成后，ZIP 文件包含数据库和索引的完整快照

### 从 ZIP 文件恢复

1. 进入索引状态页面，点击「从 ZIP 恢复」
2. 选择之前导出的 ZIP 文件
3. 如设置了密码，输入解密密码
4. 系统验证文件完整性后开始恢复
5. 恢复完成后，应用自动重启并加载恢复的数据

### 恢复后的死目录处理

从备份恢复后，原备份中引用的监控目录可能在当前系统上不存在（例如路径不同或目录已删除），这些目录称为**死目录**。

系统提供两种处理方式：

| 方式 | 说明 |
|------|------|
| **重映射路径** | 将死目录映射到新路径，保留该目录下的所有索引数据 |
| **移除目录** | 删除死目录及其对应的索引数据，释放存储空间 |

进入设置 →通用标签页，在「目录管理」中可查看死目录列表并选择处理方式。
