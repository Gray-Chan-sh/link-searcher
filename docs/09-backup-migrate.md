# 第九章：数据备份与迁移

> 存储位置、手动备份、自动备份、迁移数据、跨平台索引。

---

## 步骤 1：了解数据存储位置

Link-Searcher 的所有数据存储在本地：

| 平台 | 数据目录 |
|------|---------|
| macOS | `~/Library/Application Support/link-searcher/` |
| Windows | `%LOCALAPPDATA%\link-searcher\` |
| Linux | `~/.local/share/link-searcher/` |

目录内容：

| 文件/目录 | 说明 |
|-----------|------|
| `data.db` | SQLite 数据库（文件追踪、配置、AI 会话等） |
| `.ls-index/` | Tantivy 搜索引擎索引文件 |
| `chat_history.json` | AI 聊天记录（会话与消息） |
| `app.log` | 应用运行日志 |
| `backups/` | 自动备份存储目录 |
| `models/sensevoice/` | SenseVoice 语音识别模型 |
| `models/asr/` | VAD + 说话人分离辅助模型（可选） |

> 应用设置（`config.json`，含 API Key 等）位于配置目录而非数据目录：macOS/Linux 为
> `~/.config/.link-searcher/`，Windows 为 `%APPDATA%\.link-searcher\`。
>
> 语音模型只需下载一次，升级重装后仍在。开发版（`npm run tauri dev`）优先从项目目录读取，打包版只认数据目录。

## 步骤 2：手动备份

1. 进入**设置 → 备份**标签页
2. 点击「立即备份」按钮
3. 系统会在线备份 `data.db` + 索引目录到备份位置（若存在，`config.json` 与
   `chat_history.json` 会一并写入备份）
4. 备份完成后，状态栏会显示结果

## 步骤 3：配置自动备份

1. 进入设置 → 系统标签页
2. 开启「自动备份」开关（**默认关闭**）
3. 设置备份间隔天数（如 7 天）
4. 系统会按间隔自动创建备份（应用运行期间由后台维护线程检查，每 60 秒一次）

> 备份存储在数据目录的 `backups/` 子目录中。
> 备份失败不会记「已备份」时间，下一轮会自动重试；正在扫描或正在恢复备份时会跳过本次，等下一轮。

## 步骤 4：迁移数据

如果需要将数据迁移到新位置：

1. 进入设置 → 通用标签页
2. 点击「数据目录」旁的「迁移数据」按钮
3. 在弹出的对话框中选择目标目录
4. 系统自动复制所有数据到新目录
5. 复制完成后，应用自动重启并使用新目录

> 迁移前请确保目标目录有足够的磁盘空间（至少为原数据体积的 1.5 倍）。

## 步骤 5：了解跨平台索引

文件路径在数据库和索引中存储为**相对路径**（相对于监控目录根），而非绝对路径。

这意味着：
- 两个完全同步的目录在不同操作系统上可共享同一份索引数据
- 例如：macOS 上索引的目录，复制到 Windows 后可直接使用
- 适合在多个设备间共享索引

## 补充：增量备份与 ZIP 导出

### 增量备份链机制

每次手动或自动备份时，系统采用增量备份链：

1. 首次备份创建完整快照，包含数据库和所有 Tantivy 索引段（segment）
2. 后续备份通过**硬链接**（hard link）共享未变化的索引段，仅复制新增或修改的段文件
3. 备份链自动合并：当快照数达到 **10 个**时，系统将最早的 N-1 个快照合并为一个整合基线快照，释放冗余空间

这种方式既节省磁盘空间，又保留完整的备份历史。

### 导出为 ZIP 文件

备份链可以导出为单个 ZIP 文件，便于离线存储或跨设备传输：

1. 进入**设置 → 备份**标签页，点击「导出为 ZIP」
2. 选择保存位置和文件名
3. 可选择是否启用 **AES-256 加密**（需设置密码）
4. 导出完成后，ZIP 文件包含数据库和索引的完整快照

### 从 ZIP 文件恢复

恢复分**两步**，目的是先确定「目录落到本机哪里」，再覆盖数据 —— 避免恢复后按备份里的
**原机旧路径**扫描，把当前机器上「路径存在但内容不同」的目录误当成变更而删除/覆盖记录。

1. 进入**设置 → 备份**标签页，点击「选择 ZIP 恢复」
2. 选择之前导出的 ZIP 文件（此步只**只读**列出备份中的监控目录，不会改动当前数据）
3. 弹出「恢复前指定目录」对话框：备份里每个监控目录都需指定落位方式

| 落位方式 | 说明 |
|------|------|
| **保留原路径** | 沿用备份里记录的原路径（同机恢复、路径未变时选它） |
| **指定目录** | 选择一个本机目录替代原路径；选择后会做**只读预检**，显示「命中 found/tracked，大小一致 size」 |
| **停用扫描** | 保留该目录的配置与已索引数据，但**不再扫描 / 监控它**（可在「目录管理」中随时重新启用） |
| **移除** | 不要该目录，恢复后连同其已索引内容一并清理（磁盘上的文件不动） |

4. 若某目录预检**命中率偏低**，界面会提示「目标目录内容可能与备份不符」，需勾选确认后才能继续
   （「保留原路径」同样会预检：原路径若**存在但内容不符**，命中率会很低并触发确认）
5. 若备份完整性校验（`snapshot.json` 的逐文件 sha256）发现异常，顶部会提示「发现 N 处异常（可继续）」
6. 点击「开始恢复」，系统校验映射（必须覆盖全部目录、目标路径互不重复）后覆盖数据
7. 恢复完成后，应用自动重启并加载恢复的数据，扫描用的是你指定的路径

> **一并恢复的内容**：除 `data.db` 与索引外，备份中的 `chat_history.json`（聊天记录）与
> `config.json`（应用设置，含 API Key、模型选择、自动备份开关等）也会写回本机，随后应用重启生效。
> 备份里**没有**这两份文件时，本机现有文件会被保留（不会被删除）。
> 对话框顶部会列出「将一并恢复」的内容，便于确认。

> 「恢复前指定目录」保证恢复后**不会**再用备份里的旧路径扫描；未在本机存在的目录可「移除」，
> 需要保留数据的目录请「指定目录」到它的新位置。
>
> **停用**与「移除」的区别：「移除」会删除该目录的配置**与其全部已索引内容**；「停用」只关闭
> 扫描开关，配置和数据都留着，之后在**设置 → 目录管理**里点「启用」即可恢复扫描。停用的目录
> 不参与启动扫描、全量/增量扫描、文件监控与「重建索引」。

### 停用（暂停扫描）目录

在**设置 → 目录管理**中，每个目录右侧有「停用 / 启用」按钮。停用的目录：

- 不参与**启动扫描、全量扫描、增量扫描、定时扫描与文件监控**
- 仍显示在目录列表中，并带「已停用」标记
- 已索引数据**保留**（可继续被搜索命中）
- 手动对该目录发起的操作（如单独重扫该目录）仍会执行

> 「重建索引」会清空并从磁盘重新扫描，**停用的目录不在扫描范围内** —— 因此重建后该目录的
> 索引内容会被清空（配置文件与数据库中的目录记录仍在）。如果你只是暂时不想扫描它，
> 重建前请先「启用」；如果永远不要它，请用「移除目录」。

### 恢复后的死目录处理

若某次恢复时对目录选择了**保留原路径**、而该路径在当前系统上并不存在（例如路径不同或目录已删除），恢复后它会被列为**死目录**。

系统提供两种处理方式：

| 方式 | 说明 |
|------|------|
| **重映射路径** | 将死目录映射到新路径，保留该目录下的所有索引数据 |
| **移除目录** | 删除死目录及其对应的索引数据，释放存储空间 |

进入**设置 → 备份**标签页，在「失效目录」区块中可查看死目录列表并选择处理方式（重映射 / 移除）。
