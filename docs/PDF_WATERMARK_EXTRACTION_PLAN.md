# PDF 文字提取与水印处理完整方案

> 状态：方案已确认，尚未实施代码改造
>
> 目标：只清洗索引/检索文本，不修改用户原始 PDF；覆盖纯文字 PDF、纯扫描 PDF、文字层水印、扫描图水印，以及“文字层是水印、正文在扫描图中”的混合 PDF。

## 1. 结论

方案可行，但不能把 PDF 中的所有文字直接拼接成一个结果。

正确模型是：

```text
文字层和图像 OCR 都只是候选来源
        ↓
逐页判断来源可信度和水印污染
        ↓
选择正文来源，必要时按区域合并
        ↓
质量验证与安全回退
        ↓
写入索引文本
```

最重要的规则：

> 如果页面的 PDF 文字层主要是水印，而正文位于扫描图像中，则文字层只能作为水印证据，不能作为正文；正文必须来自扫描图 OCR。

## 2. 当前实现与实测结论

### 2.1 当前已有能力

- `lopdf` 解析 PDF 页面和文字层；
- `pdftotext` 文字层兜底；
- `pdfimages` 提取嵌入图像；
- `pdftoppm` 渲染页面；
- Windows OCR、Apple Vision、PaddleOCR、Tesseract 多引擎；
- 扫描页检测、文字层质量判断、OCR 并发闸门和 PaddleOCR EnginePool；
- `pdftotext -bbox-layout` 词坐标水印检测原型；
- 水印检测后按几何剔除、正文不足时升级 OCR、无法恢复时保留带水印文字层的安全回退。

### 2.2 三个样本的实际情况

| 文件 | 页面事实 | 正确正文来源 |
|---|---|---|
| `起诉状.pdf` | 整页扫描图；文字层基本是 `陈/骥/X` 水印碎片 | 扫描图 OCR |
| `1-法庭审理笔录（第二次）.pdf` | 整页扫描图；文字层含正文 OCR + 大量斜向水印碎片 | 清理后的文字层，清理不可靠时扫描图 OCR |
| `20140920.pdf` | 扫描表格/执照图；文字层主要是水印碎片和局部验证信息 | 扫描图 OCR，可信验证信息可补充 |

实测发现，第二个文件原文字层约 49.3% 非空行属于水印/噪声碎片。当前“文字层足够长就接受”的策略会错误采纳它。

## 3. 页面分类状态机

每一页独立分类，不再只对整个 PDF 做一次决定。

### 3.1 页面输入特征

收集：

- PDF 文字词及坐标：`text, x, y, width, height`；
- 文字行、文字块、旋转/方向；
- 页面是否存在整页图像；
- 图像覆盖率、分辨率、编码；
- 文字层非空字符数、文本密度、水平阅读流比例；
- 水印候选的页内/跨页重复模式；
- 图像 OCR 的区域和置信度（引擎支持时）。

### 3.2 四类页面

#### A. 纯文字页面

```text
无整页扫描图 + 文字层水平、连续、内容充足
→ 使用 PDF 文字层
→ 删除已确认的水印文字块
```

#### B. 纯扫描页面

```text
有整页扫描图 + 无可用文字层
→ 忽略文字层
→ OCR 扫描图
```

#### C. 水印文字层 + 扫描正文

```text
有整页扫描图 + 文字层稀疏/斜向/重复/主要为短碎片
→ 文字层只用于识别水印
→ 不把文字层作为正文
→ OCR 扫描图
```

这是 `起诉状.pdf`、`20140920.pdf` 的主要路径。

#### D. 扫描正文 + OCR 文字层 + 水印

```text
有整页扫描图 + 文字层包含连续正文和水印
→ 先按坐标清理文字层
→ 清理后正文完整、质量足够：使用清理后的文字层
→ 清理后不完整或不确定：使用扫描图 OCR
```

这是 `1-法庭审理笔录（第二次）.pdf` 的路径。

## 4. 水印检测：不使用预设字典

不使用“陈骥”“律师事务所”等预设词典，也不建立跨文档碎片字典。

原因：

- 未知水印无法覆盖；
- 同一个人名或机构名可能是真实正文；
- 字典会产生跨文档误伤；
- 字典只能看到已经被删除/记录的碎片，无法解决首次出现的新水印。

### 4.1 文字层/矢量层检测信号

所有信号都基于当前页面自身的几何和重复结构：

1. **跨页同位重复**：同一文字块或文字块簇在不同页面的归一化坐标附近重复出现；
2. **斜向方向**：词块基线或相邻词的连线呈稳定非水平角度；
3. **独占短行**：词块单独占一行，且不属于正常阅读流；
4. **固定间距链**：相邻词的 `dx/dy`、字号、间距稳定；
5. **页内重复**：同一对角链在页面中按固定偏移重复；
6. **正文对比**：正文通常形成水平行和连续语义块，水印通常跨越正文且不参与正常行布局。

### 4.2 判定原则

不能依赖一个条件单独删除。建议：

```text
跨页同位重复
且（斜向方向 或 独占短行/固定间距链）
且不属于正常水平阅读块
→ 判定为文字层水印
```

单页 PDF 没有跨页证据时，只允许高置信度的几何对角链触发；否则不删除，宁可交给 OCR/质量审计。

### 4.3 图像水印检测

图像水印分两种：

1. 水印很浅，OCR 本身不读取：直接采用 OCR 结果；
2. 水印被 OCR 读取：保存 OCR 区域坐标，判断其是否与跨页固定位置/斜向结构吻合；只有确认后才过滤。

图像级 mask、修补和 inpainting 不作为第一版默认路径，因为可能损伤印章、手写字和表格线。只在 OCR 仍产生明显水印且质量验证失败时，作为二次重试。

## 5. 文字层与图像 OCR 的融合

### 5.1 不允许直接拼接

禁止：

```text
PDF text layer + OCR(full page) → 直接 join
```

这样会导致重复正文、水印混入和阅读顺序错乱。

### 5.2 优先级

```text
文字层正文可靠且水印可精确删除
    → 清理后的文字层

文字层主要是水印或来源不确定
    → 图像 OCR

两者都可靠但内容互补
    → 按页面区域和坐标合并
```

### 5.3 区域合并

需要合并时：

1. 文字层词块和 OCR 文本框都保留坐标；
2. 对重叠区域进行匹配；
3. 文字层与 OCR 重叠且文字层质量更高时保留文字层；
4. 文字层为空或被判为水印的区域使用 OCR；
5. 按阅读顺序排序；
6. 对相同区域只保留一个来源。

不能使用“全文字符串去重”代替坐标去重。

## 6. 安全回退策略

水印清洗不是终点，任何时候都不能因为删除水印而丢正文。

```text
原始文字层
    ↓
检测并尝试清洗
    ↓
清洗后正文覆盖率/密度足够？
    ├─ 是 → 使用清洗结果
    └─ 否 → OCR 扫描图
              ↓
          OCR 质量足够？
              ├─ 是 → 使用 OCR
              └─ 否 → 回退原文字层并标记 watermark_residual
```

必须记录：

- `watermark_detected`；
- `watermark_removed`；
- `body_source`：`pdf_text` / `image_ocr` / `hybrid` / `fallback_text`；
- `watermark_residual`；
- 清洗前后字符数和正文覆盖率；
- OCR 是否升级、升级原因和耗时。

## 7. 对现有代码的调整计划

### 7.1 保留

- `pdfimages` 优先提取 JPEG；
- `pdftoppm` 旋转和渲染兜底；
- Windows OCR / Apple Vision / PaddleOCR / Tesseract 引擎；
- OCR Gate、EnginePool 和现有质量评分；
- `pdftotext -bbox-layout` 的并发读取实现，避免大 stdout 管道死锁；
- “OCR 失败时回退带水印文字层，不写空正文”的安全原则。

### 7.2 修改

#### `src-tauri/src/extractor/pdf.rs`

- 把水印判定从“全文 PDF 级”改成逐页；
- `is_image_based_scan` 不再只因文字层长度足够就接受；
- 扫描页文字层先进行来源分类；
- 文字层主要是水印时直接走图像 OCR；
- 清理后正文不足时按页升级 OCR；
- 返回 `body_source` 和水印状态。

#### `src-tauri/src/extractor/pdf/watermark.rs`

- 删除跨文档字典和预设碎片逻辑；
- 增加跨页同位聚类；
- 增加页面内固定偏移链检测；
- 保留高置信度对角链检测；
- 输出词块级删除集合，而不是只输出字符串 token；
- 允许同一字符串在正文中保留，只删除对应坐标词块。

#### `src-tauri/src/extractor/pdf/ocr.rs`

- 返回 OCR 文本框/区域坐标；
- 支持页面级 OCR 结果和来源标记；
- 只在必要时做图像水印 mask 二次尝试；
- OCR 结果质量不足时必须回退，不得静默成功。

#### `src-tauri/src/extractor/quality.rs`

- 增加 `body_source`、水印状态和正文覆盖率；
- `WatermarkResidual` 进入质量审计；
- 水印清洗后字符数减少不能单独作为成功依据。

#### `src-tauri/src/db/mod.rs` / `indexer.rs`

- 删除 `watermark_tokens` 表及其读写逻辑；
- 保留最终提取元数据；
- 不使用跨文档知识影响其它文档判断。

## 8. 性能与开销

### 8.1 低成本路径

- `pdfinfo`/`pdfimages -list` 元数据检查；
- 文字层坐标解析；
- 页面内几何聚类；
- 水印文字层清洗。

这些成本远低于一次 OCR。

### 8.2 仅在必要时执行的成本

- 扫描图 OCR；
- OCR 失败后的高 DPI 重试；
- 图像水印 mask；
- 区域级二次 OCR。

### 8.3 不采用的默认优化

- 不对每页固定执行两次 OCR；
- 不默认全图二值化；
- 不默认 inpainting；
- 不默认引入 ONNX Runtime；
- 不为每个文档创建预设水印词典。

## 9. 验收测试矩阵

### 必测样本

1. `起诉状.pdf`：水印文字层 + 扫描正文；
2. `1-法庭审理笔录（第二次）.pdf`：正文文字层 + 水印文字层 + 扫描图；
3. `20140920.pdf`：扫描表格/执照 + 水印；
4. `证据目录.pdf`：短行表格反例；
5. `万1.pdf`：含真实“上海小城律师事务所”的发票反例；
6. 无水印纯文字 PDF；
7. 无文字层纯扫描 PDF；
8. 单页 PDF；
9. 旋转页面、竖排文字、表格和印章页面。

### 验收指标

- 水印文字层 + 扫描正文：正文必须来自扫描图 OCR 或可靠区域合并；
- 三个样本的正文关键词召回率不得下降；
- 反例中的短表格字段、姓名、机构名不得被按关键词删除；
- 清洗失败不能产生空正文；
- `watermark_residual` 必须可追踪；
- 正常 PDF 的输出与改造前一致；
- 平均提取耗时、P95 耗时和峰值内存有记录；
- `cargo test`、`cargo check`、semgrep ERROR 级检查通过。

## 10. 实施顺序

### Phase 1：来源感知，不改默认结果

- 增加逐页 `body_source` 诊断；
- 记录文字层覆盖率、图像覆盖率和 OCR 候选；
- 对三个样本生成决策日志。

### Phase 2：修复混合页面选择

- 扫描图 + 水印主导文字层 → 忽略文字层，使用 OCR；
- 文字层正文可靠 → 保留清理后的文字层；
- 增加安全回退。

### Phase 3：无字典几何水印清理

- 删除跨文档字典；
- 实现跨页同位聚类和逐词坐标删除；
- 加入反例回归测试。

### Phase 4：区域融合和图像水印二次处理

- 文字层与 OCR 区域级合并；
- 必要时图像 mask + 二次 OCR；
- 对复杂表格、印章、竖排和单页文档做专项回归。

## 11. 明确边界

不存在对任意单页、同色、同方向、与正文完全融合的水印都能 100% 自动识别的算法。系统应优先保证：

```text
不丢正文 > 不误删正文 > 尽可能减少水印
```

对于无法高置信度区分的情况，保留原文并标记质量问题，比静默删除真实正文更安全。
