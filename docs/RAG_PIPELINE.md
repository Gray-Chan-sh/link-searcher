# 检索问答流程：用户提问后发生了什么

> 本文只描述**系统的行为**——它对你的问题做了什么处理、按什么顺序、在哪一步可能丢失信息。
> **不涉及代码实现**（不含文件、函数、常量）。要查具体参数与实现，见
> [设计手册](ARCHITECTURE.md) 与 [检索评测基线](rag-eval-baseline.md)。

---

## 一句话概括

> 把你的一句话，**改写 → 限定范围 → 四路并行粗筛 → 按"多通道共识"合并 → 精读模型复核 → 取前若干份装进上下文 → 交给大模型**，并全程可追溯。

---

## 完整流程

### 1. 剥离指令
输入里的 `@文件`、`@目录`、`/范围:`、`/ext:`、`/date:`、`/模糊:` 等限定会被**从问句里摘出来**，转成"检索条件"，剩下的文字才是真正要回答的问题。

> 摘出的内容**不会**参与关键词匹配，因此不会干扰检索。

### 2. 改写问题
系统不直接拿原话去搜，而是先改写：

- **指代补全**：问题里出现"它""这个""上述"或问题过短时，结合上下文补全
- **大模型改写**：再用大模型提炼一次，产出真正用于检索的实词

> **只看你过去问过的话，不看助手之前的回答。** 因为助手回答中的否定性表述（"没有""不属于"）会污染检索方向。
> 改写失败或超时（5 秒）会**自动退回**到未改写的版本，不阻塞流程；同时有实体兜底——上文的实体词会被强制带上。

### 3. 确定搜索范围
第 1 步摘出的条件在此生效：限定目录、指定文件、文件类型、日期区间。

> **范围跨轮累积**：这一轮限定的范围，下一轮继续有效，直到你说"全库"清除。

### 4. 四路同时检索

| 方式 | 擅长 |
|---|---|
| **按字面找** | 精确术语、案号、人名、金额 |
| **按整篇意思找** | 换个说法也能找到（语义相近） |
| **按段落意思找** | 长文档里的某一段在讲这件事 |
| **按文件名找** | 文件名本身就是答案线索 |

四路**同时进行**、互相补充。若未启用语义能力，则只有"按字面找"和"按文件名找"两路。

### 5. 合并排序（核心逻辑）

四份结果合并时**不是简单相加分数**，而是看"**在几个通道里被找到**"：

> - 一份文件如果在**多个通道里都排得靠前** → 位置更靠前
> - 只在**一个通道里**排名很高、其他通道完全没找到 → 位置吃亏

⚠️ **这是"字面完全匹配却排不进前三十"的首要原因。**

### 6. 精读重排
对合并后的**前 50 份**，再请一个**专门做精读的模型**逐份细读打分（把问题和材料放一起比对，比前面的粗筛准得多）。

> 为了稳妥，**最终位置只采纳它 30% 的意见，其余 70% 沿用原排序**——防止精读模型把本来排对的长文档压下去。
> 精读模型不可用时**自动跳过**，不影响正常使用。

### 7. 选材与配额
- 选出**最多 30 份**材料
- 按预算分配每份的篇幅；**超长的会被截断**，并标注"材料过长已截断"，让模型知道自己没看全
- 每份材料带**会话内稳定编号**（同一文件跨轮编号一致），并**声明本轮提供的编号集合**（防止模型引用未提供的编号）

### 8. 找不到就拒答（严格模式，可选）
开启"仅依据文档"时，若范围内**一份材料都没找到**，系统**直接拒绝回答**，而不是让模型编造。

> 目录范围内的零命中会**兜底**：先把该目录下的文件纳入材料，避免误拒。

### 9. 生成与引用
材料 + 对话历史 + 你的问题一起交给大模型，**逐字流式返回**。

回答中的 `[N]` 引用会被**校验与补全**，只允许指向本轮实际提供的材料；编号在**同一会话内保持稳定**（同一文件跨轮编号一致）。

### 10. 同时展示给你

| 面板 | 内容 |
|---|---|
| **检索依据** | 每份材料来自哪里、用什么方式找到的、字面分/语义分/融合分、是否被改写命中 |
| **推理过程** | 从「改写 → 范围解析 → 检索 → 材料组装 → 调用模型 → 完成」的全链路时间线 |

## 关键截断链（信息在哪一步被丢掉）

系统在多个环节做取舍，**每一步都会丢东西**，顺序如下：

```
四路候选 → 合并排序 → 精读窗口（前 50） → 注入材料（前 30 份） → 材料总上限
                                                                    ↑
                              最容易出问题：「检索到了，但模型其实没看到」
```

| 环节 | 行为 | 后果 |
|---|---|---|
| **合并排序** | 按"多通道共识"排序 | 单一通道的强匹配文档排名吃亏 |
| **精读窗口** | 只精读前 50 份 | 排在 50 名之后的正确文档**没有翻身机会** |
| **注入上限** | 只装前 30 份 | 第 31 名之后对模型完全不可见 |
| **材料总上限** | 拼接后还有一道总量上限 | **排在列表里、却在截断点之后的材料，模型看不到** |

> ⚠️ 最后两条是"检索依据面板里明明有这份文件，但回答却没用上"的典型原因。

## 已知的薄弱场景

根据评测基线（见 `docs/rag-eval-baseline.md`）：

| 场景 | 表现 | 原因 |
|---|---|---|
| **合同/协议类条款查询** | 最弱（0/6 进入前 10） | 条款高度模板化、跨文件重复，缺少专有名词锚点 |
| **法规类条款查询** | 较弱（4/6） | 文件可跨案复用，同类文件多 |
| **语义化措辞的查询** | 较弱（约 45%） | 措辞与文档用词不重合，字面通道失效 |
| **取值型提问**（"X 是多少"） | 最好（约 96%） | 问句里带实体名，字面通道有强锚点 |

> **规律**：**问句越"像一份需求陈述"，越难检索；越"像文档里的原话"，越容易。**
> 系统目前基于"与问句的相似度"找材料，而用户要的是"包含答案的材料"——两者在取值型提问上恰好重合，在条款/清单型提问上系统性分离。

### 引用与编号体系

> 来源：对一次真实多轮问答（律师查询不动产资料，3 轮追问）的全链路复盘，2026-09-20。

| 现象 | 表现 | 原因 |
|---|---|---|
| **编号每轮重排** | 同一份材料在第 2 轮的编号与第 1 轮不同；助手还会把"历史编号已失效"这句系统提示**复述进回答** | 材料每轮从 `[1]` 重新编号，历史编号作废；系统主动声明旧编号失效 |
| **越界（悬空）引用** | 回答声明"编号 `[1]`-`[23]`"却出现 `[25]`——指向一份模型**从未看到**的材料 | 材料因总长上限被截断后，"声明范围"按**实际可见材料数**算，但"补全/校验引用"时的上界用的是**检索到的全部材料数**，两者不一致 |
| **泛化误挂** | "以当地不动产登记中心要求为准"这类套话被挂上无关材料编号 | 自动补引用只看"句子与材料的关键词重合度"，泛词（如"不动产登记中心"）也能触发；**重合 ≠ 支撑** |
| **跨案污染** | 全库提问时其他案件卷宗被大量带入（实测单轮字面命中 4000~6000 份） | 未限定范围时全库检索；"利害关系人/判决/裁定"等跨案通用词无区分度；缺"同一案件自动聚焦" |
| **指代丢失** | 追问里的"他/它"在改写后消失，未补成具体人名 | 改写只回看用户问过的话、且每条被截断；大模型改写超时会退回机械拼词 |
| **来源等级错位** | 拿"当事人上诉状"当作"法院认定"的出处 | 关键裁判文书未被索引/未检索到时，系统不会提示来源等级不足 |

## 待定改进（已评估，暂未实施）

### 会话聚焦：抑制跨案污染（④）

**问题**：范围未指定（全库）时，泛化的法律概念查询（如"判决书 认定 利害关系人"）会把**其它案件卷宗**大量带入材料（实测单轮字面命中 4000~6000 份，材料混入多个无关案件）。

**已评估方案（保守版）**：从会话既有证据路径推断**主目录单元**（`案件/<案名>` 取 2 段；单层目录取 1 段；出现 ≥3 次且为众数）；**仅当范围未指定时**，对不在该前缀下的命中做**软降权**（如 ×0.5）——只调次序、不排除任何文件。

**为何暂缓**：
- **软性锁定风险**：会话证据只记录"被注入"的材料 → 若新主题文档一直被降权挤出注入上限（30 份），聚焦可能**锁死在旧主题**，用户难以切换。
- **无法用"全库"关闭**：`/范围:全库` 与"从未限定"是同一状态，都会触发聚焦。
- **参数是启发式**：聚焦单位、出现阈值、降权强度都需按真实语料标定，当前无评测数据支撑。

**备选方向**：

| 方向 | 做法 | 效果 |
|---|---|---|
| 变弱 | 降权 0.5 → 0.7 | 更少挤出，锁定风险更低 |
| 仅在焦充足时降权 | 仅当在焦命中 ≥ 30 才降权 | 避免把有用的挤走 |
| 只降不挤 | 降权后仍保底注入若干份 | 跨案文档总有机会 |
| 用户可控 | 不做自动聚焦，改 UI 一键"限定到本案件" | 无锁定风险，需前端 |
| 关闭 | 不做 | 保持现状（全库无偏好） |

**结论**：需结合检索评测基线（`docs/rag-eval-baseline.md`）标定后再决定；当前保持全库检索，跨案污染由用户 `@` 显式限定范围规避。

### 多轮指代 / 问题精确性判定与收窄（⑤，方案）

**要解决的问题**：用户提问往往不精确（缺关键词、指代不明）。系统必须能**区分三种情况**，而不是一律说"材料不足"：

| 情况 | 含义 | 应对 |
|---|---|---|
| **问得清楚** | 问题自带区分信息 | 直接作答 |
| **问得不精确** | 库里**有**材料，但候选互相打架 | **收窄**（帮用户把话说清楚） |
| **库里没有** | 确实没有相关材料 | 拒答 + 建议 |

**为什么不能靠"规则表"**：人的问法无穷（指代/省略/口语/错别字/半句话…），**列不全**；而漏掉的问法会被"**自信地答错**"——这是最坏的失败模式。因此**规则不能当判定门**，只能降级为"抄近路"的提示。

#### 三层判定架构

```
① 连续信号（任何问法都能算，不依赖词表）
        ↓ 阈值（需标定）
② 语义裁判（大模型：判断"该问的是哪一个"）
        ↓
③ 安全兜底（披露式：先答 + 声明假设 + 给收窄入口）
```

**第 1 层：连续信号（"量体温"）**

- 量的是**检索分数分布的形状**：
  - **分数间隔**（第一名与第二名差多少）→ 有没有"主心骨"
  - **分布分散度**（熵/基尼）→ 材料散不散
  - **绝对相关度**（最像的那份到底像不像）→ 可能真没有
- **为什么形状能反映"问题够不够精确"**：问题里带**唯一锚点** → 只有少数文档匹配 → 分数**必然尖**；问题里**全是通用词** → 大量文档都匹配 → 分数**必然平**。所以"平" ≈ "问题没带区分信息"。（此即信息检索里的"查询性能预测"思路，**无需人工标注**。）
- **能可靠判的**：① "库里有没有答案"（所有分都接近 0 → 没有）；② "有没有把握"（平坦/多峰 → 报警）。
- **单独判不了的**：宽泛清晰 vs 真歧义——两者在分数上都"平"。**补充手段**：再看 top 命中**彼此像不像**（平坦 + 互相像 = 同一主题 = 宽泛清晰；平坦 + 互相不像 = 不同主体 = 歧义），仍是纯计算、不需词表。

**第 2 层：语义裁判（大模型）**

- 输入：**原始问句** + **候选实体清单**；输出：`{可直接答 | 歧义 | 无依据}`，若歧义则指出候选。
- **分工（重要）**：**"库里有没有答案"由第 1 层判**（大模型会幻觉，不可信）；**"问的是哪一个"交给大模型**（这是常识/语义判断，它擅长）。
- 可并入现有"改写问题"调用，**几乎不增加延迟**。

**第 3 层：披露式兜底**

- 判不准时：**先按最可能作答 + 显式声明假设 + 给一键收窄入口**，**永不静默猜测、永不硬拦**。

#### 锚点 = 实体（不是罕见词，也不是文件夹）

**核心**：用户问的是"**哪一个**"，所以锚点必须是**实例实体**，而不是"碰巧少见的字串"，也不是"文件所在的目录"。

- **实例实体**（具体某一个）：人名、机构名、案号、具体文件名、日期 → **可当锚点**。
- **类型名词**（某一类）：判决书、委托书、不动产、利害关系人 → **不是锚点**。
- **稀有度**只用来衡量"锚点多强"（到处都出现的实体是弱锚点），**不决定"是不是"**锚点。
- **为什么不用文件夹**：文档可能散落各处，按目录分组会失效；而**实体是内容**——同一实体的文档，无论放在哪，都能靠"都含这个实体"归为一组。
- **"尖峰 + 位置散落"恰恰是锚点在工作的证据**：top 命中散落在不同目录、却都含同一实体 → 正是该实体把它们连成一组。

**实体从哪来（内容驱动）**：

| 手段 | 抓什么 |
|---|---|
| 分词词性标注 | 人名 / 地名 / 机构 / 专名 / 数词 / 时间 |
| 正则模式 | 案号、日期、文号 |
| 文件名本身 | 文件名里的专名（靠的是文件名里的**字**，不是它所在的目录） |
| 语料共现（可选） | 与"原告/被告/律师/公司/案"等标记词共现的词 |

**关于 NER（结论：现阶段不需要）**：

- 我们要的不是"识别所有实体"，而是"认出用户指哪一个 + 能给候选"；且候选是**给用户选的**，因此更需要**召回**而非极致精度。
- 通用中文 NER 训练于新闻语料，抓不到本领域关键的**案号/文书名/当事人角色**——**领域不匹配**；且引入模型有下载/内存/延迟/维护成本，与本项目离线轻依赖取向冲突。
- 替代：**分词词性 + 正则 + 文件名**，且**只需对"问句 + top-K 命中"做**（不触碰索引期、零模型）。
- **何时再评估**：建标注集测出**召回不足**时，且优先轻量/领域方案。

#### 收窄机制（"精确化"怎么做）

判定为"不精确"后，**不是拒答**，而是**把隐含锚点显式化并注入检索**：

1. **候选聚类**：把 top 命中按"**含哪个实体**"分组（不是按目录）；
2. **让用户选**：给一张选择卡（`你问的是 ①汪均益 ②姚远 ③…？`），候选来自**真实命中里的实体**，一定言之有物；
3. **一键注入**：用户选后，把该实体写入**检索查询（词）**与**检索范围（路径）**两层 → 立即重跑 / 下一轮生效；
4. **可逆**：范围可 × 删除、可"全库"清空。

**收窄发生在两层**：查询层（补实体词）+ 范围层（补路径）。只做一层不够。

**锚点来源的优先级**：用户显式（@文件/@目录）> 候选聚类让用户选 > 会话上下文推断（**须披露**）> 追问补全。

#### 标定要求

判定依赖若干阈值（分数间隔、分散度、共现窗口…）。**没有标注数据就调不出正确阈值**——需先建小 golden 集（每题标 `宽泛可答 / 不精确需收窄 / 无答案`），用检索评测流程标定。（这也是 ④ 被暂缓的同一原因。）

### 其他待定

- **⑥ chunk 质量 / 来源等级**：检索片段常含页眉水印噪声；只索引到当事人书状、索引不到裁判文书时，会以书状充"法院裁判"的出处。
  - **去噪放哪做**（已评估，结论待定）：噪声有**两种伤害**——**排名污染**（检索阶段，问答时过滤修不了）与**上下文污染**（注入阶段，可过滤）。故推荐**中间路线**：**索引期"非破坏性标记"（保留原文、给 chunk 打噪声标记）+ 检索期按需降权/过滤**。理由：删除不可逆且随语料漂移（与可追溯/审计冲突）；问答时过滤管不到排名池。纯全文搜索不应过滤（用户搜的就是那些字节）。

## 排查线索

当回答不对或查不到时，依次看：

1. **检索依据面板** —— 目标文件在不在里面？
   - **不在** → 检索阶段就没找到（合并排序/通道覆盖问题）
   - **在，但序号靠后** → 排序问题
   - **在，序号也靠前，但回答没用** → 可能是材料总上限把它截掉了
2. **推理过程时间线** —— 看改写后的查询串是否丢失了关键实词；看范围解析是否意外缩小了范围
3. **严格模式** —— 是否因"范围内无命中"而拒答
